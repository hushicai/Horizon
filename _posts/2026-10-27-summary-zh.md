### [Type Server Protocol（TSP）技术介绍与社区反响](https://github.com/microsoft/pylance-release/blob/main/docs/tsp/type-server-protocol.md) ⭐️ 7.0/10

微软发布了 Type Server Protocol（TSP）提案，旨在为 Python 提供专用的类型服务器接口，与通用的语言服务器协议 LSP 形成区分。basedpyright v1.40.2 的维护者 DetachHead 曾批评 TSP，而 astral 的 Ty 类型检查器则计划支持 TSP，这在 Python 类型检查社区中暴露了协议兼容性的分歧。

hackernews · adamnemecek · 10月26日 18:14 · [社区讨论](https://news.ycombinator.com/item?id=50248371)

**「语言服务器协议与 TSP 的关系」** 语言服务器协议（LSP）是连接编辑器与语言服务器的标准协议，提供自动补全、代码跳转等功能。微软引入的类型服务器协议（TSP）是专门为 Python 类型检查设计的替代方案，基于 LSP 的概念但针对 Python 类型系统进行优化。这一变化对 Python 类型检查工具链产生了重要影响，社区正在讨论其与现有 LSP 工具的兼容性和优势。

**「兼容性影响」** 基于 basedpyright v1.40.2 的维护者对 TSP 的批评表明，该协议与现有 LSP 工作流的兼容性存疑，可能导致依赖 basedpyright 的开发者需要重新配置类型服务器或权衡工具选择。

**「社区争论」** 有评论质疑将通用协议名用于仅支持 Python 的 TSP，特别是来自 LSP 公司。同时 basedpyright 维护者批评 TSP，而 astral 的 Ty 将支持它，反映出社区在协议统一与工具分歧上的分裂。

### [Deepity 0.1.0a3 发布：手调 C++/CUDA 预测编码库，CPU 基准优于 jpc、ngc-learn](https://www.reddit.com/r/MachineLearning/comments/1xg6sqa/deepity_a_handtuned_ccuda_predictive_coding/) ⭐️ 7.0/10

Deepity 0.1.0a3 已以 MIT 许可首次公开发布，提供 C++20 核心、Python 绑定（nanobind）和 PyPI 包 pydeepity，供预测编码网络（PCN）研究者和开发者使用。CPU 路径是目前成熟并经过基准测试的部分：在 12 代 i7-12700H 笔记本上，784-512-512-10 Sigmoid 网络、T=20 步稳定、批量 250、100 个 epoch 的匹配配置下，Deepity 达到 98.21% 精度并耗时 487.5 秒，优于 jpc（JAX）的 97.55%/531.4 秒和 ngc-learn 的 98%/1707.7 秒；PyTorch 反向传播参考点为 97.51%/627.8 秒，但作者称这不是公平比较，因为 PC 每批次执行 20 步稳定。CUDA 后端已能构建和运行，但大规模训练仍在调优，卷积使用 im2col+cuBLAS 而非 cuDNN，且作者未公布 CUDA 与 CPU 的对比数字。

reddit · r/MachineLearning · /u/Important-Home4431 · 10月26日 19:34

**「背景」** 预测编码网络中，每层维护对自身状态的局部信念，并与上层自顶向下的预测比较；训练交替进行“稳定”（各层本地减少预测误差）和仅依赖本层误差的权重更新，不需要其他层权重的转置，也无需保留反向计算图。这与反向传播的单一全局误差信号不同，是 Deepity 从零实现的算法基础。

**「影响」** 对希望在 CPU 上实验预测编码的用户而言，可直接通过 pip install pydeepity 安装并使用，但应注意这是 0.1.0a3 版本的单人维护 alpha 软件；CUDA 后端虽可构建运行，但大规模训练尚未调优且未发布经验证的 CUDA-versus-CPU 性能，不宜作为生产级 GPU 方案采用。
