### [Microsoft Proposes Type Server Protocol for Python Type Checking](https://github.com/microsoft/pylance-release/blob/main/docs/tsp/type-server-protocol.md) ⭐️ 7.0/10

Microsoft has published a specification for the Type Server Protocol \(TSP\), a JSON-RPC protocol designed to serve Python type information to editors and tools. The protocol is documented in the Pylance repository and aims to provide a dedicated interface for type queries, distinct from the Language Server Protocol \(LSP\). Major Python type checker maintainers have responded differently: the maintainer of basedpyright has criticized the design, while Astral has indicated that their Ty type checker will support TSP.

hackernews · adamnemecek · Oct 26, 18:14 · [Discussion](https://news.ycombinator.com/item?id=50248371)

**「Background: The Language Server Protocol and Python Type Checking」** The Type Server Protocol \(TSP\) is Microsoft&\#x27;s proposed alternative to the Language Server Protocol \(LSP\) for Python type checking. LSP, also originated by Microsoft, is the established industry standard for editor-to-language-server communication, defining messages for features like autocomplete, go-to-definition, and diagnostics. In the Python ecosystem, multiple LSP-based type checkers exist—including basedpyright \(a fork of Pyright\) and Pylance \(Microsoft&\#x27;s commercial offering\)—but maintainers have raised concerns about LSP&\#x27;s adequacy for type-specific queries, which is the gap TSP aims to fill. The tool results confirm LSP&\#x27;s role as the incumbent protocol, with the python-lsp-compare repository providing a benchmark harness for comparing Python LSP implementations, underscoring the protocol&\#x27;s centrality to the tooling landscape that TSP now seeks to complement or replace.

**「Community Discussion」** Commenters questioned why the protocol uses a generic name when it appears Python-specific, given Microsoft&\#x27;s role in creating the language-agnostic LSP. Others asked for clarification on why LSP&\#x27;s existing capabilities are insufficient for Python type queries, and what advantages TSP offers over other typed JSON-RPC frameworks such as tRPC. The basedpyright maintainer&\#x27;s prior criticism and Astral&\#x27;s planned support for Ty were cited as key points of divergence among implementers.

### [Deepity: A Hand-Tuned C++/CUDA Predictive Coding Library Outperforms jpc and ngc-learn on MNIST](https://www.reddit.com/r/MachineLearning/comments/1xg6sqa/deepity_a_handtuned_ccuda_predictive_coding/) ⭐️ 7.0/10

Deepity is a new open-source predictive coding library with a C++20 core, hand-written AVX2/AVX-512 SIMD kernels \(via SLEEF for transcendentals\), OpenBLAS/MKL GEMM, and a CUDA backend using cuBLAS, CUTLASS, and CUDA graph capture. It ships as pip-installable pydeepity with nanobind Python bindings and offers several PCN variants including classic settling, Direct Kolen-Pollack feedback, and a configurable &\#x27;kitchen sink&\#x27; network. On a matched 784-512-512-10 sigmoid MNIST benchmark \(T=20, batch 250, 100 epochs, AdamW, 12th-Gen i7-12700H laptop CPU\), Deepity achieved 98.21% accuracy in 487.5s versus jpc \(JAX\) at 97.55% in 531.4s and ngc-learn at 98% in 1707.7s; a PyTorch backprop reference on the same architecture scored 97.51% in 627.8s. The library reports sustained kernel throughput of ~690 GFLOPS/s on a Google Benchmark harness and ~675 GFLOPS/s in the end-to-end MNIST run. This is alpha software \(v0.1.0a3\), solo-maintained: the CPU path is mature and benchmarked, while the CUDA backend builds and runs but large-scale ImageNet training is still being optimized, and the convolution path uses im2col+cuBLAS rather than cuDNN.

reddit · r/MachineLearning · /u/Important-Home4431 · Oct 26, 19:34

**「Background」** Predictive coding \(PC\) is an alternative training paradigm to backpropagation. Instead of a single global error signal flowing backward through a stored computation graph, each layer in a predictive coding network maintains a local belief about its state and compares it against a top-down prediction from the layer above. Training alternates between &\#x27;settling&\#x27;—where every layer locally reduces its own prediction error over several steps—and a weight update that only uses that layer&\#x27;s own error, eliminating the need for weight transposes and backward graph storage. Existing PC implementations such as jpc \(JAX\) and ngc-learn have been available, but Deepity is the first from-scratch C++/CUDA implementation with hand-tuned SIMD and BLAS kernels aimed at raw CPU performance.

**「Impact」** ML researchers and performance-conscious developers now have an open-source, MIT-licensed predictive coding library with a native C++/CUDA implementation that reportedly outperforms existing PC frameworks \(jpc, ngc-learn\) on CPU benchmarks while matching or exceeding their accuracy. The pip-installable pydeepity package with a PyTorch/Keras-like API lowers the barrier to entry for experimenting with predictive coding. However, as alpha software, it is not yet suitable for production or large-scale GPU training: the CUDA backend remains under optimization, convolution does not use cuDNN, and the project is solo-maintained, so community support and long-term maintenance are uncertain.
